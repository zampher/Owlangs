# BBox 偏差分析报告

## 偏差产生的环节分析

从对比结果来看，bbox偏差主要出现在以下环节：

### 1. **X0 (左边缘) - 偏差最小**
- **观察结果**：大多数 x0 差异为 0.0
- **结论**：左边缘位置准确，说明 ReportLab 渲染时正确使用了原始 bbox 的 x0 坐标
- **偏差来源**：无显著偏差

### 2. **Y0 (顶部边缘) - 小幅度系统性偏移**
- **观察结果**：y0 差异约 -1.5 points（约 1.5 点向下偏移）
- **可能原因**：
  - 坐标系统转换时的舍入误差
  - PyMuPDF 提取时的基线计算差异
  - ReportLab 文本绘制的基线位置
- **偏差来源**：**坐标转换环节**或**文本基线计算**

### 3. **X1 (右边缘) - 显著偏差**
- **观察结果**：x1 差异多为正数（25-72 points），说明渲染后的文本更窄
- **典型例子**：
  - 原始: x1=517.9, 渲染后: x1=445.1 (差异 72.8 points)
  - 原始: x1=518.9, 渲染后: x1=493.1 (差异 25.8 points)
- **根本原因**：
  - **文本换行**：ReportLab 使用 `simpleSplit` 进行文本换行，导致文本在更窄的宽度内换行
  - 原始 PDF 中的文本可能是单行，但渲染后被换成了多行
- **偏差来源**：**ReportLab 渲染环节的文本换行逻辑**

### 4. **Y1 (底部边缘) - 变化较大**
- **观察结果**：y1 差异有正有负，变化范围大（-73 到 +12 points）
- **典型例子**：
  - 差异 -19.7 points（文本变短）
  - 差异 -73.5 points（文本变短很多）
  - 差异 +12.9 points（文本变长）
- **根本原因**：
  - **行数变化**：文本换行导致行数变化
  - **行高计算**：使用固定的 `font_size * 1.2` 作为行高，可能与实际行高不匹配
- **偏差来源**：**ReportLab 渲染环节的行高和换行计算**

## 偏差产生的具体环节

### 环节 1: 原始 PDF → PyMuPDF 提取
- **状态**：✅ 准确
- **证据**：页面尺寸完全匹配（0.0 差异）

### 环节 2: PyMuPDF 提取 → ReportLab 渲染
- **状态**：⚠️ 有偏差
- **主要问题**：
  1. **文本换行**：`simpleSplit` 根据 bbox 宽度换行，但原始 PDF 中的文本可能是硬编码的单行
  2. **行高计算**：使用固定行高 `font_size * 1.2`，可能与原始字体行高不匹配
  3. **坐标转换**：y0 有约 -1.5 points 的系统性偏移

### 环节 3: ReportLab 渲染 → PyMuPDF 重新提取
- **状态**：✅ 准确
- **证据**：PyMuPDF 能够准确提取渲染后的 PDF 布局

## 关键发现

1. **X0 位置准确**：说明坐标传递正确
2. **Y0 有小偏移**：可能是文本基线计算问题
3. **X1 显著变小**：文本换行导致宽度变小
4. **Y1 变化大**：行数和行高计算导致高度变化

## 改进建议

1. **保留原始文本布局**：
   - 不要自动换行，保持原始文本的单行/多行结构
   - 或者使用更精确的文本测量来匹配原始宽度

2. **改进行高计算**：
   - 从原始布局中提取实际行高
   - 或者使用 ReportLab 的文本测量功能计算准确行高

3. **修复 Y0 偏移**：
   - 检查坐标转换逻辑
   - 考虑文本基线和 bbox 顶部的关系
